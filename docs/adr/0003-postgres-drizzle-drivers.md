# ADR 0003: Postgres with Drizzle, two drivers, migrations as a deploy step

Status: accepted (slice 2).

## Context

The domain is relational (boards, members, pipelines, stages, tasks, comments) and v1's worst data bugs were the lack of
relations: cascades done by hand and not in a transaction, a race that created duplicate memberships. Production runs on
Neon (serverless Postgres); development and CI must need no account.

## Decision

- PostgreSQL 17 and Drizzle ORM. Foreign keys with `ON DELETE CASCADE` replace the hand-written cascades; membership is
  unique on `(board_id, user_id)`; a board and its owner membership are created in one transaction.
- `DB_DRIVER=pg` (node-postgres) locally and in CI, `DB_DRIVER=neon` (the WebSocket `Pool` of `@neondatabase/serverless`)
  in production. Both support interactive transactions; the Neon HTTP driver does not, which is why it is not used.
  Same schema, same migrations, same repositories.
- Every connection gets `statement_timeout` 15 s and `lock_timeout` 5 s: a lock bug fails fast instead of piling up.
- `UnitOfWork.run` is one real READ COMMITTED transaction. Deadlocks (40P01) and serialization failures (40001) are
  retried up to three times with jittered backoff, so a unit of work must be safe to run again. Writers lock in one
  global order (boards, members, pipelines, stages, tasks) so the retry is rarely needed ([ADR 0011](0011-deletion-outbox.md)).
- Migrations are generated by `drizzle-kit` and committed. They are applied by `pnpm db:migrate`, a deploy and CI step,
  never at request time.
- `position` columns are `text COLLATE "C"` ([ADR 0012](0012-fractional-positions.md)).

## Consequences

- Integration tests run against real Postgres (a service container in CI), including cascades, uniqueness and races.
- Neon scales to zero, so the first request after idle pays a wake-up; the daily cron ([ADR 0018](0018-guest-sandbox-and-scheduled-maintenance.md))
  starts with a trivial query for that reason and the pooled connection string is used.
- The driver switch is configuration, but it is verified only against a real Neon database during go-live
  ([docs/go-live.md](../go-live.md)), because no Neon account exists in development.
